# VSlices Tooling v0.2.0-preview

`v0.2.0-preview` is an evolutionary preview line. It expands CLI operability and semantic capability from concrete evidence while preserving authority boundaries.

> Lowering may complete implementation detail. Lowering must not complete missing semantics.

## Consolidated deterministic architecture

The Ticket Support `TicketId` experiment grew enough behavior to justify a consolidation before inspecting another real `.vsir`.

The resulting internal flow is:

```text
CLI command adapter
  -> operation / coordinator
  -> project / ruleset / lineage infrastructure
  -> VSIR / target mechanisms
```

`TranspilationOperation` owns deterministic projection, `RebaseOperation` owns deterministic three-way rebase, and `LoweringCoordinator` owns `lower` policy. Command handlers no longer embed the full lowering workflow or call each other for reuse.

A single `VSlicesProjectContext` represents detected project/config/ruleset/lineage roots.

## Semantic conservation

Unknown keys now fail closed through known semantic mappings, not only at the VSIR root. The current coverage includes construction, construction steps, ensure, condition, failure and equality. Variable-key data mappings remain intentionally open.

Traits are unordered capabilities. Unknown or duplicate traits are explicit failures; current subset still requires `transform`, and `identifier` independently requires equality.

No new VSIR concept was introduced by the consolidation.

## Ruleset lifecycle

`init` and `update --ruleset` share source materialization and snapshot installation.

```text
materialize source
-> prepare selected target
-> validate prepared snapshot through target loader
-> atomic replace / rollback
```

C# snapshot validation now rejects broken loader state before swap, including missing declared files, duplicate rules, unsupported mode/renderer and empty templates.

For supported GitHub repository sources, `ruleset.ref` may resolve branch, tag or commit/direct archive reference instead of being an undocumented branch-only value.

## Lineage

The TicketId consumer experiment established that bootstrap must be non-destructive:

```text
existing conventional witness
+ no lineage
+ configured bootstrap
-> compute current deterministic projection
-> store deterministic baseline
-> preserve witness byte-for-byte
-> success
```

A later semantic change can then use the stored deterministic baseline for automatic three-way rebase.

`.vslices/lineage` is intended to be version-controlled so repository state is sufficient for continuation on another machine/CI. It remains operational evidence rather than semantic authority.

## Update surfaces

Atomic surfaces remain:

```text
vslices update --self
vslices update --ruleset
```

Plain `vslices update` and combined updates remain intentionally undefined.

## Validation expansion

A dedicated `tests/VSlices.Tooling.Tests` suite exercises Tooling orchestration through the real built CLI process. It covers project-context boundaries, lineage creation/bootstrap/rebase, source-override ancestry failure and ruleset-update preservation on invalid candidates.

CI additionally smoke-tests ruleset update and the complete lineage bootstrap -> semantic change -> automatic rebase workflow using local fixtures, not GitHub remote state.

An attempted in-process Tooling test reference exposed a case-insensitive assembly identity collision between executable assembly `vslices` and Framework assembly `VSlices`. The consolidation does not create a new assembly solely to hide that fact; it remains a documented architectural question if in-process Tooling reuse later becomes required.

## Ticket Support evidence

The sequence preserved in PR #4 is:

```text
unknown equality semantics
-> identifier/equality representation
-> C# structural lowering
-> external ordinal equality rules
-> project ruleset update
-> lineage bootstrap
-> destructive-bootstrap observation
-> non-destructive correction
-> consumer confirmation with build4.218
-> architectural consolidation
```

## Explicit non-scope

This consolidation does not add:

- normalization;
- new domain classifications or VSIR concepts;
- new target languages;
- interpretive lowering;
- Git-history ancestry reconstruction or provenance graph;
- aggregate update semantics;
- namespace path policy;
- configurable terminal themes.

The observed target-context namespace issue remains the next independent experiment only after this PR is stable.
