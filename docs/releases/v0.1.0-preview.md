# VSlices Tooling v0.1.0-preview

This document defines the intended scope and release-readiness criteria for the first VSlices Tooling preview.

The purpose of `v0.1.0-preview` is not to claim a complete VSIR execution model. It is to publish a small, coherent, testable baseline whose implemented behavior matches the architectural boundaries already documented by the project.

## Included surface

The preview includes these CLI commands:

```text
vslices init
vslices lower
vslices transpile
vslices rebase
vslices update --self
```

The implemented baseline covers:

- parsing and conservative validation of the current experimental VSIR benchmark surface;
- deterministic C# lowering when the required rules exist;
- external project-local lowering rules under `.vslices/ruleset/`;
- explicit failure when required lowering knowledge is absent;
- conservative semantic rebase over a human-edited materialization when the previous VSIR baseline is explicitly available;
- `lower` orchestration that chooses deterministic transpilation for a new materialization and rebase when the required ancestry is available;
- project-local `.vslices/config.yaml` operating policy;
- shared recursive VSIR artifact discovery with built-in exclusions and `.vslices/.ignore`;
- .NET target-context delegation and explicit namespace override;
- Native AOT distribution for the currently proven RIDs;
- Windows PowerShell bootstrap installation;
- verified standalone CLI self-update through release checksums.

## Explicitly not included

`interpretate` is not a `v0.1.0-preview` command.

The concept remains part of the lowering model: it represents interpretive lowering when deterministic rules and deterministic rebase are insufficient but semantic obligations and enough contextual evidence are available.

A first executable `vslices interpretate` surface is a candidate for `v0.2.0-preview`. Its absence from `v0.1.0-preview` is intentional scope, not an incomplete command hidden behind the release.

The following are also outside the first preview unless separately adopted before release:

- automatic provenance reconstruction for rebase;
- `vslices update --ruleset`;
- arbitrary target plugin/package systems;
- multiple production-ready target languages;
- a graphical Windows installer;
- package-manager distribution such as Winget or Homebrew;
- semantic verification beyond the currently implemented parsing/lowering checks.

## Architectural contract

The preview preserves this authority boundary:

```text
.vsir
  = semantic source

.vsir.cs
  = editable materialization constrained by the VSIR

.vslices/ruleset/
  = revisable lowering knowledge

.vslices/config.yaml
  = project operating policy

vslices executable
  = mechanisms, orchestration, safety guarantees, and target adapters
```

A missing lowering rule is not permission to infer or improvise one.

Deterministic lowering may complete implementation detail, but it must not complete missing semantics.

`transpile` must not silently overwrite an existing human-editable materialization. `rebase` must not invent ancestry. `lower` must stop when the least-powerful valid mechanism cannot be established.

## Distribution contract

The first preview is expected to publish Native AOT artifacts using the release naming contract:

```text
vslices-win-x64.zip
vslices-win-x64.zip.sha256

vslices-linux-x64.zip
vslices-linux-x64.zip.sha256
```

Windows bootstrap installation uses the repository `install.ps1` and installs the standalone executable under:

```text
%USERPROFILE%\.vslices\bin\vslices.exe
```

The installer verifies the release archive checksum before installation and adds the install directory to the user PATH unless explicitly disabled.

The same standalone executable is the authority updated by:

```text
vslices update --self
```

CLI version and project-local ruleset version remain independent.

## Release-readiness criteria

`v0.1.0-preview` should not be tagged until the branch satisfies all of the following:

- the solution builds in Release configuration;
- all automated tests pass;
- explicit namespace override works without requiring a `.csproj`;
- deterministic `transpile` is exercised through the CLI;
- `lower` creates the conventional sibling materialization;
- `rebase` is exercised through the CLI and preserves compatible human content;
- recursive discovery respects built-in exclusions and `.vslices/.ignore`;
- .NET project context delegation is exercised through the real `dotnet` tooling;
- Native AOT publication succeeds and the produced executable runs the documented command surface;
- `vslices init` creates `.vslices/config.yaml`, `.ignore`, and the selected local ruleset;
- the Windows bootstrap script parses successfully as PowerShell;
- release automation produces the documented archive/checksum names;
- README and focused documentation describe only behavior that is implemented or clearly marked as future direction;
- `interpretate` is described as future scope rather than exposed as an implemented command.

The first published release itself provides the final end-to-end evidence for remote installation and self-update against real GitHub Release assets. Any defect in that release path should be corrected in a subsequent preview rather than weakening checksum or replacement guarantees.

## Candidate next preview

The current candidate theme for `v0.2.0-preview` is interpretive lowering:

```text
vslices interpretate
```

That work should begin from concrete cases where deterministic transpile/rebase cannot faithfully resolve a materialization decision, and should preserve the policy that `lower` selects the least interpretive sufficient mechanism.

This version boundary is intentionally revisable. It records current release intent; it does not turn future design hypotheses into commitments.
